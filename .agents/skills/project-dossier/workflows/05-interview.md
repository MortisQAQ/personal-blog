# 阶段 5：面试与回填

输入：母档、简历及可选的面试问题，查实现时读技术实现概要。产物沿用用户目录；新文件使用 `面试套件.md`。只有用户要求模拟面试时才逐题互动，不重做源码归档。

先确定出口：指定单稿只生成该稿及必要备注后结束；泛化的“准备面试”默认给三分钟稿，并链接母档已有核心追问，缺少时补最小追问链；明确要完整套件才执行第 1–4 节；模拟或复盘直接进入第 5 节。

## 1. 三种叙述粒度

以相同事实生成，背景简短，重点放本人动作、机制和验证：

| 版本 | 交付形式 | 内容 |
|---|---|---|
| 60 秒 | 可自然口述的短稿 | 项目与职责、一个问题、一个关键动作、结果 |
| 3 分钟 | 可自然口述的主讲稿 | 背景与约束、核心决策、实现、验证、边界 |
| 10 分钟 | 深挖提纲及各段回答要点 | 在主讲稿上展开结构链路、备选方案、异常分支、Bug 与反思 |

若用户明确要逐字稿再展开长稿；不要用重复的免责说明凑时长。时长只是目标，未经口述计时不声称精准达标。

口述稿用第一人称自然讲述，不出现“母档写道”“给定材料显示”“根据 F1”。只把已确认本人动作放进“我做了”；团队机制写成项目行为，未知归属不擅自认领。必要限制放在相关结论旁，其余证据备注单列。

## 2. 准备可复用故事

从母档第 3 章（最难的问题）与第 6 章（失败复盘）选技术困难、排查和协作经历；旧稿已有 `D*`、`B*` 才沿用编号，无编号时用语义锚点。同一故事可回答多个问题，不为了分类另造事件。

按 STAR(R) 压缩：**情境与约束 → 本人任务 → 动作及理由 → 结果与验证 → 反思**。动作占主要篇幅，突出做了什么、如何判断、为何不采用另一做法。

Bug 故事必须保留线索、定位依据和回归方式。缺失的排查过程不能补造；没有实际 Bug 材料就列“待补案例”，以已知交付继续准备其他问题。

## 3. 生成项目特定的追问链

优先取真实评审问题、简历关键主张、核心实现分支和已知边界。外部开源题库只补考察维度，不直接搬成项目经历或无关八股题。

每个核心故事准备一条连续三层链，每层都给答案要点：

1. **实现层**：你具体做了什么？入口、状态与调用顺序是什么？
2. **决策层**：为什么这样做？不这样做会在哪种情况下出错？更简单方案呢？
3. **验证与边界层**：怎么证明有效？代价是什么？条件变化后怎么办？

每题给问题与能开口回答的短段落；证据链接和必要边界放句后，掌握度在练习记录集中保存。不要为每个问题重复六栏大表。答案深度随问题调整，不只有“看某章”。

母档第 7 章已有的追问直接链接，套件只补更深追问和口语化练习，不能重建一套独立答案源。单稿无需附题，完整套件也不复制同一事实表。

例如围绕请求版本校验：为什么要区分新旧响应 → 旧请求失败是否也要拦、能否减少请求量 → 如何分别验证回写正确性与网络成本、取消有什么额外代价。每一问都必须回到该项目的真实机制。

初次统一标“待练习”；用户实际回答后再标“能答”或“需补强”。证据不足标“资料缺口”，它与用户是否会答是两个问题。

## 4. 单独准备假设题

按项目约束挑 2–3 个相关反事实：需求变化、交互增多、依赖失败、时间缩短或重做方案。回答用「假设条件 → 判断依据 → 方案 → 代价 → 验证计划」。

明确标“假设推演”，不进入历史成果。基础知识或邻域问题按需补充，并区分本人做过、只了解接口、现学的原理，不能把理解写成贡献。

## 5. 模拟面试与错题回填

模拟时一次问一道，等待回答后针对缺口追问，不先泄露参考答案。反馈聚焦事实正确性、机制深度、取舍验证和表达清晰度，引用用户原话，不仅给分。

面试复盘每题记录：

`问题原文 → 当时回答 → 缺口类型 → 修正要点 → 母档位置 → 派生物同步 → 下次复问`

| 缺口 | 回填方式 |
|---|---|
| 实现错漏 | 先修还原稿及缺口，再同步母档中的相关解释与派生物 |
| 职责、历史或结果错漏 | 先修母档，再更新受影响的简历条目、叙述版本和题目 |
| 决策或知识不清 | 补验证过的解释；新推演明确标时序，不改写历史 |
| 只有表达冗长、顺序混乱 | 只修口述稿与练习记录，不改事实 |

保留稳定 ID 和未解决项，避免每轮重写全部材料。没有真实文件可修改时提供具体替换内容与位置，不声称已更新外部文件。整理过答案不等于掌握，下轮需复问。

## 完成检查

指定单稿只检查事实、叙述与必要边界。备考及完整套件再检查核心主张的追问链和答案依据；至少有一个可讲清的困难或交付故事。Bug、协作、指标缺材料时明确缺口，不用编造的完整故事代替。

# 阶段 3：编写与验收双档

本阶段读取入口所列的两份结构参考和写作范例。模板提供章节目的，不是填表任务；重要性决定篇幅。

## 两条阅读路径

还原稿先用一段话界定系统，再给带职责的文件树和全局调用链。随后按真实模块展开：核心状态和异步机制写短解释、契约表和关键伪代码，简单视图或工具在树或简表中说明。可复刻范围要与源码读取范围一致。

母档按七段式固定结构组织：开头几个短段落说明项目、本人边界和最值得讲的判断并附导航，随后依次是背景与目标、个人职责和边界、最难的问题、关键技术决策及备选方案、结果与证据、失败复盘和后续改进、可能被追问的问题。七段都要有，确实无内容的写明“无”及原因，不留空标题、不用推演填充。可以放一条简洁业务链路，但不搬完整目录和逐函数说明。

第 3 章与第 4 章容易写重：第 3 章交代问题怎么解决，第 4 章交代为什么选这条路而不是别的。只有具备独立判断价值的决策才在第 4 章单列，否则并入第 3 章，不为凑满结构而拆分同一件事。第 4 章要写清被否决方案错在哪，不只写“不合适”。

第 3 章每个难题用 STAR(R) 检查内容，用自然标题与段落写。重点是“为什么这样做、我具体做什么、如何验证”，不是机械的 S/T/A/R 四行。通常展开一到三个难题；没有第三个就不凑。

第 7 章给围绕主故事的三层追问及短回答要点，不能只列问题。完整口述稿、更多题目和模拟练习按需去面试套件，不要求新建档案时一口气生成所有派生文件。

## 所有权与迁移

| 内容 | 唯一详细维护位置 |
|---|---|
| 快照、文件、字段、状态、分支、代码复刻、实现局限 | 还原稿及其本地附录 |
| 背景、本人责任、历史决策、事故经过、结果口径、复盘 | 母档 |
| 精简贡献与面试练习 | 派生物，只引用上述两份 |

用相对链接连接两份主文档及附录。跨文档解释必要的因果不算重复，但不要复制完整契约、事故时间线或指标表。外部材料的关键证据需用获准的摘要留在对应章节，不能只留链接。

迁移旧母档先备份。按上述所有权拆内容，保留有效事实，同时把原 ID 对照和纠正项记到交付说明或技能评估记录。不能以“只做文风”保留已发现的事实错误，也不能借迁移改业务代码。

主文档在正文写完后直接结束，不设 `来源与核验`、`旧事实覆盖迁移`、`缺口与验收` 这类收尾维护章节，改名成 `核验记录`、`附录：来源`、`维护信息` 同样不行——问题不在标题，在于内容服务的是维护者而非读者。技术实现概要在开头交代读取范围和版本，把源码路径就近放在它解释的模块旁；母档在影响主张处写一句证据边界。集中的源码锚点表、旧事实迁移表、独立验收过程和缺口矩阵只进入交付说明、评估报告或任务回复。

删除这类章节时要一并检查正文里指向它的引用（如"具体范围见末尾"），否则会留下悬空指代。

## 两次验收

第一位读者仅拿还原稿及附录，先写出核心机制的伪代码，再用正常与相关异常输入推导状态。异步机制必须覆盖乱序、失败和清理时机；随后才对照源码。若必须猜关键变量、顺序或判断，就补稿再验证。检查只能证明所选范围，不等于整仓逐字复原。

第二位读者先只读母档开头，复述项目价值、本人动作、核心难点和结果边界；再读正文，检查故事能否继续追问，以及段落是否解释了取舍。最后核对主张与来源，重点查本人/团队、当时/现在、实现/上线、目标/实测是否混淆。

能使用独立子代理时分配不同读者，不能让作者给自己盖“独立验证”章；没有代理就如实记自查。读者结论、实际检查范围和遗留缺口简记于交付说明，不塞进任何主文档主体或结尾。

最后检查长列表、表格密度与强调噪声。数字仅提示要重读的地方，不能删必要分支去凑比例。修正文体后仍核验事实与链接；实现变更先回填还原稿，经历/指标变更先回填母档，再更新受影响的派生物。

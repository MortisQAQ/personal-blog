# 技能维护时的应用评估

常规归档无需生成整套评估报告。改技能时先固定任务、来源和验收标准，用未改版本运行基线，再执行新版本，不只让模型评价指令写得好不好。

## 三个必测场景

| 场景 | 任务 | 验收 |
|---|---|---|
| 双用途 | 同一项目既要离开仓库后还原，又要准备面试；已有冗长旧稿 | 双档互链，核心实现有复刻和分支，母档有入口与因果叙述，不等长复读 |
| 证据不足 | 只知道代码存在，明天面试，要有分量的成果 | 不冒领团队工作，不编指标或历史备选；保留可确认范围 |
| 只要口述 | 已有事实，要求三分钟讲稿 | 只给指定稿及必要备注，不附送整套备考产物；不抄字段表，个人动作真实 |

额外检查双用途场景：主文档不得以 `来源与核验`、`旧事实覆盖迁移`、`缺口与验收` 等维护章节收尾。源码锚点表、旧事实迁移表、验收范围和缺口矩阵应只出现在交付说明、评估报告或任务回复中。

任务提示只给意图和材料，不在提示里重写新版所有规则，否则无法判断技能是否有效。改动相邻技能也需单独基线与复测，不能因主技能通过就默认兼容。

## 独立验收

还原读者先只看还原稿及附录，封存其伪代码和正常/异常推导，再打开源码比较。检查关键状态、顺序、分支与边界是否需要猜测；发现错误回写文档，不替业务代码加保护。

叙述读者先看母档开头复述价值、个人边界、难点和结果，再读全文查逻辑，最后核对来源。检查是否把“代码存在”换成“本人完成”，是否用统一免责掩盖越界主张。多个子代理不能共享评判结论再称为盲评。

记录实际看过的文件与未测范围。若评估者提前看到源码，不能再称“脱离源码独立还原”；可诚实记为交叉核验。

## 机械检查

检查技能 frontmatter、相对链接和 500 行上限。对产物用相同口径统计列表项、表格行、长列表项、行内代码与加粗；代码块内符号不算叙述噪声，完整列表项需包含续行。

统计只作预警，尤其不能将还原稿的契约表与面试母档按同一阈值评分。减少反引号、增加空行或删除异常路径不等于改善写作。

## 报告限制

报告列实际失败、修改、复测和仍未确认的部分。原稿与新稿来源不同，只能描述案例观察；同材料、同任务才可作受控比较。没有多模型多项目测试，就明确未做，不声称技能已普适可靠。

# blog-content 知识库

个人前端/全栈学习与求职知识的 Markdown 源目录。**公开发布的文章只有一个来源：`posts/`**，本目录其余内容不会进入站点构建产物。

## 目录

| 目录 | 内容 | 说明 |
| --- | --- | --- |
| `front-end/` | 前端技术主线 | HTML、CSS/响应式、JavaScript/TypeScript、React、构建工具 |
| `0-Web开发基础知识/` | 通识底座 | 编程、计算机、抽象、AI 时代的知识价值 |
| `04-algorhythm/` | 数据结构与算法 | 数组、链表、栈、树、排序、动态规划、分治 |
| `05-nodejs&&npm/` | Node.js 与 npm | 运行时、模块规范、包管理；后端主线的起点 |
| `06-互联网是如何工作的/` | 网络与浏览器 | 浏览器原理、HTTP/1.1 核心特性（前后端共用） |
| `09-AI/` | AI 相关 | SSE、harness 工程、终端环境配置 |
| `面试/` | 面试与求职材料 | 简历、项目经历追问、八股整理；**本地私有**，已被 `.gitignore` 忽略 |
| `杂谈/` | 随笔 | 与教程主线无关的杂记 |
| `posts/` | 公开发布文章 | 站点构建的唯一内容来源，改动需通过 frontmatter 校验 |

根目录的 `.docx` 是简历源文件，属于本地材料，与站点发布无关。

## 目录约定

- **按技术域归档**：前端相关问题一律放进 `front-end/` 对应子目录，不在 `blog-content/` 根目录新建零散技术目录。
- **目录内用数字前缀表示阅读顺序**（如 `front-end/03-javascript-typescript/3.1-basic/`），跨目录一律用相对链接，便于跟随目录移动。
- **`posts/` 之外的内容不参与站点构建**：移动、重命名其他目录不会影响线上文章。

## 全栈规划

`front-end/` 只承载前端。后续做全栈时按同一口径扩展根目录，例如新建 `back-end/`（Node 服务端、数据库、工程化），公共底座（`0-Web开发基础知识/`、`04-algorhythm/`、`06-互联网是如何工作的/`）保持中立，不塞进任何一端。

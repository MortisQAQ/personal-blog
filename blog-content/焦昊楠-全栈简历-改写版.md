## 二、全栈简历的底层逻辑：只讲一条链

全栈岗招聘方唯一想确认的事：**给你一个需求，你能不能独自把「数据 → 服务 → 契约 → 界面 → 上线 → 观测」走完，并且出错时能自己定位。**

所以每条经历都按这个骨架写：

1. **链路是什么**（一句话说清你负责的那条端到端路径）
2. **你在哪一层做了设计决策**（契约、状态、协议、数据模型 —— 选一个说透）
3. **踩坑与取舍**（为什么不用现成方案，成本是什么）
4. **结果**（业务指标 + 工程指标，各一个）

## 六、项目经历（改写）

### 项目一：Triple Uni —— 港三校留学生社交平台（万级注册 / 千级日活）
全栈开发 · 微信小程序原生 · Node 云函数 · PHP 接口层 · MySQL · Next.js

- **帖子时间线与热门榜**：定义 `/post/list/*` 接口契约（`{token, page}` → `{code, one_list, is_last}`），把公开 / 私密 / 本校 / 跨校四种可见性收敛到 SQL 层而非前端过滤，分页用子查询定位边界避开深翻扫描；热门榜做成**离线打分 + 在线只读** —— 定时任务扫最近 1000 帖，按「浏览对数 + 去重评论与关注 + 媒体权重」打分并叠加**半衰期一天的指数衰减**（机构号 ×1.5），Top 50 落表供接口直接排序，读路径零计算。
- **会话与并发续期**：服务端 JWT（HS256，按端 7 / 30 天）+ 验签后二次查库做准入（失效 801 / 不存在 802 / 冻结 803 / 封禁 804），客户端统一请求层按业务码分流；定位并修复「首屏并发过期导致重复登录、token 互相覆盖」的缺陷，改为**单飞（single-flight）续期** —— 以旧 token 为锁 key，同一时刻仅一次重登、其余请求排队重放，4 次 `wx.login` 降为 1 次刷新 + 4 次重放。
- **年度总结（端到端）**：与统计服务约定**按页分片**的返回结构 `{user_id, generated_at, pages:{pageN}}`，20+ 屏各自消费一块语义数据（陪伴天数、注册顺序、校内排名、24 小时活跃分布、时间胶囊）；前端 Next.js App Router 静态导出部署 GitHub Pages，身份从 URL token 解析，并保留 mock 开关支持前后端并行开发。将年度实现抽成 `template/`（配置 + 翻页引擎 + 单屏容器 + 数据层），下一年复制即起步。上线 5000+ PV，空窗期用户活跃度 +50%。
- **多态内容与首屏**：帖子以单个 `media` JSON 字段承载文章 / B 站 / 网易云 / 投票四类内容，由统一装配层归一成可渲染 DTO，新增类型只加「写入接口 + 装配分支 + 渲染器」；第三方检索与小程序码生成下沉到 Node 云函数。首屏图片走 CDN + 本地持久化缓存（缓存记录带源 URL 做版本比对，命中即跳过开屏素材接口），首屏可见时间缩短约 1500ms。
- **埋点与统计**：曝光 / 停留埋点采用双标识（客户端持久匿名 ID + token 反查登录用户）与 `event_id` 幂等去重，批量攒发 + 短超时失败即丢；跨天去重由服务端按「用户 × 帖子 × 天」聚合，统计任务定时落表，为热门榜与年度总结提供数据源。

### 项目二：A 股今日异动 —— AI 驱动的异动内容生产与触达

- **承接页（stocks_h5）全栈交付**：PIA SSR 直出 + 代码懒加载 + 自研轻量分时线（拒绝为一条线引入 35KB 图表库），秒开率（LCP ≤ 1s）由 10% 提升至约 75%；A/B 实验页面点击转化 +10%、到达率 +5%。
- **可观测口径治理**：统一上报 latency / retCode / logId；ready 判定采用「业务码成功 **且** 标题摘要非空」双层口径，避免接口 200 但内容未生成的空壳页被算作达标。

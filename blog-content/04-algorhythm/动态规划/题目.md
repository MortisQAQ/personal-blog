leetcode 300

原始思路很简单：分治。
要想找到整个数组的最长递增子序列，先拆分为子问题：找到以数组内每个元素为开头的最长递增子序列。递归来解决这个子问题。然后再合并：取最长的。

把它写成状态定义，就是以整个数组 `arr` 作为状态：

```text
dp[arr] = arr 的最长递增子序列长度
```

---

## AI 点评

**结论：递归逻辑是对的，问题出在「状态定义」上。**

你的思路能算出正确答案（见第 1 节），但 `dp[arr]` 这个状态有两个致命问题：

1. **状态是数组，子问题无法复用。** 每个子问题的数组都不一样，状态空间是所有子序列，规模指数级；即便加记忆化，键也得是整个数组内容，命中率极低。
2. **只返回长度，丢掉了「结尾是谁」。** 拼接时需要知道子序列结尾的值，`dp[arr]` 给不了；而且它没有可推进的下标维度，套不进数学归纳法。

标准解法只做了一件事：**把状态从「数组」换成「索引」，并加上「以 `nums[i]` 结尾」这一约束**：

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

注意这是给原问题**加约束**，不是简化——换来的是可以按 `i` 从小到大递推。

---

## 1. 你的递归是成立的

```javascript
function LIS(arr) {
  if (arr.length === 0) {
    return 0;
  }

  let best = 1;

  for (let i = 0; i < arr.length; i++) {
    const x = arr[i];
    const sub = [];

    // 取 arr[i] 前面且值小于 x 的元素
    for (let j = 0; j < i; j++) {
      if (arr[j] < x) {
        sub.push(arr[j]);
      }
    }

    // 以 x 结尾的 LIS 长度 = 1 + LIS(sub)
    best = Math.max(best, 1 + LIS(sub));
  }

  return best;
}
```

**为什么对。** `sub` 里所有元素都小于 `x`，所以 `sub` 的任意递增子序列都能直接接在 `x` 前面，形成以 `x` 结尾的递增子序列。遍历每个 `x` 取最大，就是答案。

例如 `nums = [2, 5, 3, 4]`，对 `4` 有 `sub = [2, 3]`、`LIS([2, 3]) = 2`，所以以 `4` 结尾的 LIS 长度 = `1 + 2 = 3`，得到 `[2, 3, 4]`。

**代价。** 每次递归都要真的构造一个新数组 `sub`，子问题之间无法共享结果。

## 2. 为什么 `dp[arr]` 用不了

- **状态爆炸**：状态是数组本身，不同子问题对应不同数组；加记忆化后键是数组内容，几乎不命中。无记忆化时复杂度接近指数级。
- **无法转移**：DP 靠数学归纳法——先假设 `dp[0..i-1]` 已知，再推 `dp[i]`。而 `dp[arr]` 里根本不存在可以按顺序推进的下标。

## 3. 从 `dp[arr]` 到 `dp[i]`

你的递归里，对每个 `x = nums[i]` 实际构造的是：

```text
sub_i = [nums[j] | j < i 且 nums[j] < nums[i]]
```

并计算：

```text
以 nums[i] 结尾的 LIS 长度 = 1 + LIS(sub_i)
```

关键观察：`nums` 是固定不变的，`sub_i` 只是「前缀中比 `nums[i]` 小的那些元素」。因此**不必真的构造 `sub_i`**，只要取这些下标 `j` 对应 `dp[j]` 的最大值：

```text
dp[i] = 1 + max{ dp[j] | j < i 且 nums[j] < nums[i] }
```

没有满足条件的 `j` 时：

```text
dp[i] = 1
```

最终答案：

```text
max(dp)
```

换句话说：

```text
dp[i] 等价于 1 + LIS(sub_i)
```

## 4. 为什么必须加「以 i 结尾」

如果只定义：

```text
dp[arr] = arr 的 LIS 长度
```

那么子问题只返回一个长度，不知道「结尾是谁」；但拼接时，恰恰需要知道结尾值。

例如 `nums = [2, 5, 3, 4]`，子数组 `[2, 5, 3]` 的 LIS 长度是 2，但它可能是：

- `[2, 5]`，结尾是 5；
- `[2, 3]`，结尾是 3。

此时再来一个 `4`：`[2, 3]` 能接，得到长度 3；`[2, 5]` 接不上。所以只知道「长度 2」不够，必须知道结尾是谁。把这条信息编码进状态，就是：

```text
dp[i] = 以 nums[i] 结尾的 LIS 长度
```

## 5. 标准解法

```js
function lengthOfLIS(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(1);

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  return Math.max(...dp);
}
```

## 6. 一句话总结

- `dp[arr]`：状态是数组，信息不全（丢了结尾）、无法复用，退化成指数级递归。
- `dp[i]`：把状态参数化成「原数组 + 结尾索引」，并加上「以该索引结尾」的约束，于是能用 `dp[j] → dp[i]` 递推，复杂度降到 \(O(n^2)\)。

两者的关系不是「简化」，而是**换状态 + 加约束**。
